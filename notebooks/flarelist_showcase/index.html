STIX L3 flare list: request for feedback

Solar Orbiter / STIX · preliminary flare list, version V05 · November 2026

Dear colleagues,

the STIX team is preparing the first release of the STIX L3 flare list for the Solar Orbiter Archive (SOAR). Before we publish it, we would like to hear from you: from the STIX team and from everyone who works, or plans to work, with STIX flares. This page has a notebook that walks through the flare list, the data files, and how to send us your feedback.

⚠ Preliminary test release, for feedback only.

The content, the columns and their definitions, and the values themselves may still change.

Please do not use these files for scientific analyses or publications. Use the flare list for science only once it is published in SOAR.

One flare list of possibly several

A flare list is defined by the way its flares are detected: what counts as a flare, and when it starts, peaks and ends. This version takes the operational flare list of the STIX Data Center as input (detected in the STIX quicklook light curves) and adds the values computed in the STIX ground processing: peak values, background, location, observing geometry and the Solar Orbiter campaign. This is what the sdc in the product name stix-flarelist-sdcloc stands for.

The processing is open for more flare lists: future ones may be built around other detection algorithms and other criteria of what a flare is, with the same set of computed values. So feedback on the computed values helps every future flare list, too.

What we would like to know

First: the data in the flare list files

Our main interest is the content of the flare list files:

  • Does it support your usual use cases, for example the way you look for specific flares?
  • Is something typical missing: a column, a value, a description that is unclear?
  • Only a few standard header keywords of a file are searchable in SOAR. For the monthly flare list files we reuse them for dedicated search options: the smallest / largest flare (net peak flux at 1 AU) and the shortest / longest flare duration (section 7 of the notebook). Are these the right values to search by, or would others in these keywords serve you better?

The flare list will be published as monthly files in SOAR, one file per month. For this feedback round only, we also merged the monthly files into a year file and a mission file (January 2022 to August 2026), so that you can easily look up your favourite flares, the ones you know well from your own work. Check the numbers we computed for them: peak counts and fluxes, background, location, observing geometry. Detailed feedback on these calculations is very welcome, e.g. a value that looks wrong, a different result from your own analysis, or a definition you would compute differently. To look at a flare in the notebook, put its flare_id into SHOWCASE_FLARE_IDS in section 2 (choose the mission data set for flares outside 2023).

Second: working with the flare list in stixpy

All plots and filters in the notebook work directly on the plain data, on purpose. In stixpy we plan a rich wrapper class (a Product) that gives you convenient access to the flare list and built-in plotting routines, so you don't have to write them yourself. A preliminary version is shown in this demo: stixpy flare list demo.

You can give feedback on this next step in a separate GitHub issue: stixpy issue #268. Keep in mind that it is a chicken-and-egg problem: first we need to get the underlying data right, then the way to work with it.

The data files

All three files have the same columns; they differ only in the period they cover, and so in the time it takes to download, load and filter them. The mission file with almost 100,000 flares is the one to look up any flare, but it takes noticeably longer; the month file is quick; the year file is in between and is the notebook default.

How to get started

The notebook needs Python 3.12 or newer (as stixpy) and these packages (requirements.txt):

packageversionused for
numpy≥ 2.0arrays
astropy≥ 6.0reading the FITS file, units, times, coordinates
sunpy≥ 6.0solar coordinate frames
matplotlib≥ 3.8plots
pandas≥ 2.0tables and time handling
jinja2≥ 3.0table styling
jupyterlab≥ 4.0running the notebook
ipywidgets≥ 8.0optional: radio buttons to choose the data set
stixpyoptional: only section 6, opening the data files of one flare
  1. Unpack the zip, or put the .ipynb (and requirements.txt) into an empty folder.
  2. Create a virtual environment and install the packages: 
    python -m venv venv
source venv/bin/activate        # Windows: venv\Scripts\activate
pip install -r requirements.txt
  3. Start Jupyter, open STIX_L3_flarelist_showcase.ipynb, choose the data set in section 2 and run all cells: 
    jupyter lab

If the chosen data file is not in the notebook folder, the notebook downloads it once into that folder and uses it from there next time.

How to send feedback

  • Preferably as a comment in the GitHub issue: STIXCore issue #462.
  • Already raised? If someone has already made your point in the issue, please comment on it or at least add a 👍 (+1) reaction. That shows us how important a point is to the community and helps us decide what to do first.
  • If GitHub is not possible for you: send an email to nicky.hochmuth@ateleris.ch.

What happens with your feedback

  • Obvious errors (wrong values, broken columns, misleading descriptions) will be fixed before the first release in SOAR.
  • New requests (additional columns, values or header keywords) will be collected and prioritised, and may come in a later version of the flare list. Your comments and 👍 reactions in the issues help us set the priorities.

Thank you for your time and your feedback!
